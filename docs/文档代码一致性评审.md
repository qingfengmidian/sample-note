## 1. 结论摘要

- **总体一致性良好**：M0~M9 已交付功能中，编码探测级联、epub 双导航优先级、txt 分块加载契约、保存回退链、草稿三重清理、设置持久化模型等核心行为与文档描述**逐项吻合**，且关键边界（toc href 锚点剥离、head 文本泄漏、恢复越界 clamp）均有代码注释与真机记录互证。
- **发现 1 项高优先级功能缺口**：F2.6"可手动切换编码"**从未实现**（代码、测试、git 历史均无），但需求（高优先级）、设计 §3.2/§8、用例 TC-F2-15 三处文档均仍描述该能力，属文档与代码的实质性偏离。
- **发现 1 项中优先级行为缺陷**：CUSTOM 字体在导入后无法经任何"切换字体"入口再次选中（循环序列不含 CUSTOM），重新导入是唯一途径且产生孤儿字体文件。
- 另有文档漂移 6 项、代码质量/健壮性问题 7 项、UI/UX 问题 8 项，详见 §3~§5。

### 2.2 差异与缺口项

**G1（高）F2.6"可手动切换编码"未实现。**
需求 F2.6（高优先级）明确要求"自动探测编码……**可手动切换**"；设计 §3.2 与 §8 风险表均写明"探测结果可由用户在阅读界面手动覆盖并即时重载"；用例 TC-F2-15（P1）描述了切换操作。但代码中阅读界面菜单仅有"预览/源码、编辑"，底部工具条无编码入口；全仓 grep（`Charset|编码|TC-F2-15`）在 UI 层零命中，git 历史亦无实现记录。三份文档与代码实质偏离，且为高优先级需求。建议：M10 设置面板落地时在"排版"组补编码切换项（仅 txt 显示），或正式评审后将 F2.6 手动部分降级/删除并同步三份文档。

**G2（中）CUSTOM 字体无法再次选中。**
`ReaderViewModel.cycleFont` 与 `SettingsScreen.nextFont` 的循环序列均为 `CODE→SERIF→SANS`，不含 CUSTOM；当当前字体为 CUSTOM 时 `indexOf` 返回 -1，一键即跳回 CODE，之后**无任何 UI 路径可重新选中 CUSTOM**，只能在设置页重新导入——而 `importCustomFont` 每次以 UUID 新建副本，旧字体文件不被删除，产生孤儿文件。与 F2.4"选择即时生效并持久化"的预期交互不符。建议：循环序列在 `customFontPath != null` 时纳入 CUSTOM；切换离开 CUSTOM 或重新导入时清理旧文件。

**G3（低）设计文档 §3.5 的 `DocumentRepository` 在代码中不存在。**
架构图与仓库表均列出 `DocumentRepository`（"按 URI 调解析层得到 Document"），实际实现将该职责折叠进 `ReaderViewModel`/`EditorViewModel`（各自调用 `FileOpener`+`ParserFactory`）。功能无缺失，但分层契约与代码不符，且解析分发逻辑在两个 ViewModel 中重复（`parseBytes` 的 when 分发各写一份）。建议：补一个轻量 `DocumentRepository` 收敛重复，或将设计文档 §3.5 修订为现状。

**G4（低）进度写入时机与文档表述不符。**
设计 §3.3 写"退出时写入 Room，重开时恢复"；实现为 `onFirstVisibleParagraphChanged` 每段变化即 `persistProgress` → 每次滚动停顿产生一次 Room upsert。实现方向（更防丢）可以接受，但快速滚动下写库频率偏高，且文档未更新。建议：文档改为"滚动即写（防抖）"，代码侧加 300~500ms debounce 或退出时兜底写。

**G5（低）TC-F1-05 交互与实现不符。**
用例写"单条**左滑**删除"，实现为行尾"删除"文字按钮。功能等价，建议修订用例描述（按钮方案对无障碍更友好，建议保留实现改文档）。

**G6（低）代码注释残留旧数值。**
`ReaderScreen.kt:239` 注释仍为"超出可编辑上限（**>10MB**）置灰"，实际上限已是 2MB（`MAX_EDITABLE_BYTES = 2 * 1024 * 1024`，M8 收尾已把文案与文档改齐，此处遗漏）。同理 `app/proguard-rules.pro` 注释仍提"android.icu"（该方案 M3 已推翻）。

**G7（提示，非缺陷）设计文档 REV5/REV6 已领先代码。**
设计 §3.1 模型含 `Document.toc`、`Chapter.images/styles`、`ParagraphImage`、`ParagraphStyleHints`、`TocEntry`，§3.2/§3.3 含 md 目录与 epub 图文/CSS 设计——这些属 M11 未开工范围，不参与对比。但设计文档当前是"现状+未来"混合体，后续读者无法区分哪些已落地。建议：在 §3.1/§3.2/§3.3 的 M11 段落加"（M11 待实施）"显式标注，或拆分"目标设计"附录。`AGENTS.md` §3 目录描述亦有同类漂移（"MainActivity 当前起点为 fixtures 入口，M4 将换 HomeScreen"——实际起点已是 home）。

## 4. 代码质量与健壮性评估（移动开发视角）

**C1（中）epub 全量内存驻留。** `EpubParser.parse` 先 `readAllBytes` 读入全书字节，`readZip` 再把每个条目解压进 `Map<String, ByteArray>`——峰值内存 ≈ 原书 2 倍以上（字节数组 + 解压后全量条目）。对图文类 epub（几十 MB 常见）存在 OOM 风险。M11 已规划缓存目录解压（`cache/epub/<hash>/`），建议该方案提前到图片需求之前单独落地，正文解析也改为从缓存目录流式读章节而非整书驻留。

**C2（中）编辑器保存的字符集与换行符静默转换。** 编辑载入经 `lines()` 拆分、保存时 `joinToString("\n")` + UTF-8 写回：GBK 文件保存后变 UTF-8、CRLF 文件变 LF。对"记事本式"工具属可接受的既定设计（设计 §3.4 明确 UTF-8 写回），但 CRLF→LF 未在任何文档中声明，建议在 §3.4 补一句"保存统一为 LF 行尾"。

**C3（中）撤销粒度为逐击键。** 每次文本变化即入栈，100 步上限 ≈ 100 个字符，长句输入后撤销体验碎。建议按"停顿 300~500ms 或词边界"合并入栈。

**C4（低）`extractParagraphs` 的 XHTML 抽取循环内无 `ensureActive()`。** 取消粒度为"逐章"，单个大章节（如整书一章的 epub）解析中途退出不能及时取消，与 §3.2"逐章/逐块循环内 ensureActive()"的契约略有出入。

**C5（低）保存临时文件校验失败仍继续写回。** `writeTempFile` 返回 null（缓存写失败/校验不通过）时 `save()` 未中止，仍执行 `writeBackWithFallback`——此时"先校验再一次写回"的防截断保证已失效。建议 tempFile 为 null 时直接 `FailedSaveAs`。

**C6（低）`onPicked` 对不支持格式也先取持久权限。** 权限授予发生在嗅探之前，`.pdf` 等不支持文件的持久授权被无谓保留。建议先嗅探（读头 256 字节不需要持久权限）再授权。

**C7（低）ACTION_VIEW 与编辑现场竞争。** 编辑中（dirty）经外部"打开方式"唤起时，`pendingViewUri` 由 HomeScreen 的 `LaunchedEffect` 消费——Navigation Compose 下非栈顶目的地不进入组合，该意图会被延迟到用户退回首页时才突然触发导航，且完全不经过编辑器的三选退出拦截。建议：意图处理上移到 MainActivity 层直接导航，或对 dirty 状态先弹确认。

另：`ReaderScreen` 的 `pendingParagraph` 用 `remember` 而非 `rememberSaveable`，旋转屏幕恰好发生在换行切换重组之间时位置保持会断（窗口极小，低优先级）。

## 5. UI/UX 评估（设计专家视角）

**U1（高）应用没有图标。** `AndroidManifest.xml` 无 `android:icon`，`res/` 下仅有 `values/strings.xml`——发布包在桌面显示系统默认机器人图标。v0.0.1 既已作为发布版本，至少应补一个自适应图标（adaptive icon，前景矢量 + 背景色即可，零素材成本）。

**U2（中）窗口主题硬编码 Light 且未做沉浸式。** `android:theme="@android:style/Theme.Material.Light.NoActionBar"` 始终浅色，未 `enableEdgeToEdge`；阅读主题为"夜间黑"时状态栏/导航栏仍是系统浅色底，正文全黑、上下两条亮边，夜间体验割裂。建议改 DayNight 主题 + `enableEdgeToEdge()`，状态栏颜色跟随阅读主题背景。

**U3（中）循环式单键切换效率低。** 行距 4 档、主题 5 态、字体 3 态全部"点一下走一步"的循环按钮，主题从"跟随系统"到"夜间黑"需点 4 次且无当前态预览。这正是 M10 设置面板要解决的事——建议 M10 面板中主题/字体改为**带选中态的分段选择器（SegmentedButton）或单选列表**，不要沿用循环逻辑。

**U4（中）md 源码/预览切换的位置语义有偏差。** 两个视图共享同一 `LazyListState`，但源码 item=段落、预览 item=MarkdownBlock，索引不同义；切换后停留在"同序号的不同内容"上，TC-F2-20"切换不丢位置"实际只保住了列表序号。M11 的 block↔段落索引映射（评审 S4）应顺带覆盖**切换**场景，不只覆盖目录跳转场景。

**U5（低）编辑器不尊重 wrapMode。** 阅读设置为"不换行"时编辑区仍软换行（BasicTextField 默认），与 F3.3"全局共享同一套设置"的字面承诺有出入（设计上 F3.3 只列了字号/行距/字体/主题，不含换行——建议文档显式说明换行模式不作用于编辑器，消除歧义）。

**U6（低）"测试样本"开发入口随 release 发布。** `FixtureEntryScreen` 读 debug assets，release 包中该入口指向空列表页。建议该入口仅 debug 构建显示（`BuildConfig.DEBUG`），`DelegatingFileOpener` 的 asset 分支同理。

**U7（低）空态/错误态无操作引导。** 阅读错误页与"文件为空"均只有一行居中文字，无返回/重试按钮；首页空态文案提到了"打开文件"按钮但未给出可点击引导。建议错误态附"返回"动作，空态附主操作按钮。

**U8（低）首页信息密度与视觉层级偏简。** 最近文件行仅有"格式 · 时间"副标题，无格式图标/类型徽章区分 epub 与 txt；单条删除按钮与行点击区相邻有误触风险。可后续版本加格式徽标、删除改为滑动或长按菜单（届时与 TC-F1-05 用例修订一并考虑）。

良好实践（值得保持）：交互控件 48dp 与 contentDescription 覆盖全面；主题前景/背景成对且四套对比度全部 ≥9:1（远超 4.5:1 硬要求，见附录）；对话框内容抽成无状态 composable 供 Robolectric 直驱的测试设计干净实用。
