## 0. 计划原则

- **每步可测试可验证**：每个里程碑（M）都有明确的验证手段（自动化用例编号 / 手工验收步骤）和完成标准（DoD），未通过验证不进入下一步。
- **依赖优先**：解析层（纯逻辑，可单测）先于 UI；被依赖的基础设施（设置存储、FileOpener 桩）先于使用方。
- **测试先行**：fixtures 在 M1 全部就绪；解析层按 TDD 方式先写用例再实现（PR 分两次提交：先仅测试→CI 红，再实现→CI 绿）。
- 验证列中 `TC-*` 编号均指《测试用例》V1.0-REV3。
- 人天按 1 名熟悉 Kotlin/Compose 的工程师专职估算；多人并行见 §3 依赖图。

## 2. 分步明细

### M0 工程骨架与 CI（1~2d）

- 内容：Gradle 工程（Kotlin + Compose + Material 3，minSdk 26/targetSdk 34）、单 Activity + Navigation 空壳、GitHub Actions 工作流跑 `assembleDebug` + `testDebugUnitTest`。
- 依赖清单（版本经团队评审后锁定）：Compose BOM、Material 3、Navigation Compose、Lifecycle ViewModel Compose、DataStore Preferences、Room（runtime + compiler ksp）、Kotlinx Coroutines、JUnit4、Robolectric、Compose UI Test（ui-test-junit4）、androidx.test。
- 验证：CI（GitHub Actions）绿；空壳 App 在 API 26 模拟器上启动不崩溃。本地脚本仅作开发者自检辅助，不替代 CI。
- DoD：CI 绿；后续每个里程碑合入前 CI 必须保持绿。

### M1 测试夹具 + 设置基础设施 + FileOpener 桩（2~3d）

- 内容：
  - 按《测试用例》§0 清单生成全部 fixtures（含 `hybrid.epub`、`bad_decl.epub` 等）；**用 Gradle task（Kotlin `java.util.zip`）生成 epub 夹具**，统一工具链，不引入 Python 依赖。
  - `ReadingSettings`/`ReadingTheme`/`ReaderFont` 数据模型；`SettingsRepository`（DataStore）读写；DataStore/Room 迁移策略：V1.0 阶段 Room 用 `fallbackToDestructiveMigration`，DataStore 键变更需兼容读（缺省回退默认值）。
  - **FileOpener 接口 + 桩实现**：`interface FileOpener { suspend fun open(uri: String): InputStream }`，桩实现从 `assets/fixtures/` 读取内置样本——供 M3 在 SAF 就绪前开发阅读器；M4 替换为 SAF/ContentResolver 实现，接口不变。
- 需求映射：F2.3/F2.4/F2.5/F4.3 的存储部分。
- 验证：单测——设置的写入/读回（含行距 Int 百分值无精度漂移、theme=null 语义）；fixtures 校验 task 确认样本编码与结构符合描述；FileOpener 桩读取 assets 样本成功。
- DoD：设置单测全绿；fixtures 齐套且校验通过；FileOpener 桩可用。

### M2 文档解析层（纯逻辑，TDD，3~5d）

- 内容：`ParseException` 体系；`TxtParser`（BOM → ICU `CharsetDetector`，置信度 < 50 视为失败 → GBK → Latin-1）；`PlainTextParser`（md/xml）；`EpubParser`（container/OPF/spine、epub3 nav.xhtml 优先 + NCX 回退、XHTML 编码防御（`XmlPullParserException` 时回退 UTF-8 重解析）、剥标签降级（仅 `XmlPullParserException`/`IOException` 触发））；`ensureActive()` 取消支持。
- 需求映射：F2.1/F2.6/F2.7 的数据部分；NF-稳定性。
- 验证（全部自动化）：TC-UT-01 ~ TC-UT-06b、TC-UT-04c（性能断言 ≤200ms）、TC-UT-13。
- TDD 验收：每个 parser 的 PR 分两次提交——先仅含测试（CI 红），再提交实现（CI 绿）。
- DoD：解析层单测全绿，红绿过程在 PR 历史中可复现；EpubParser 对 `broken.epub` 抛出的是 `MissingOpf` 而非笼统异常。

### S1 SAF Provider 技术探针（spike，1d，M2 后、M3 前）

- 内容：独立探针工程（不入主仓或 `spike/` 目录不打包），在目标真机 + 至少一个云存储 Provider（Google Drive/OneDrive）上验证：`OpenDocument`、`takePersistableUriPermission`、`openOutputStream("wt"/"w")` 的实际行为。
- 验证：产出探针报告——确认/修正设计 3.4/3.6 节的假设（`"wt"` 支持度、截断行为、持久权限有效性）。
- DoD：报告结论明确；若推翻假设，回到设计文档修订后再进 M4。

### M3 阅读器核心（txt/md/xml 单章阅读，3~5d）

- 内容：`ReaderTextView`（WRAP / NO_WRAP + 位置保持）、`SelectionContainer` 长按复制、字号/行距（`lineHeight = fontSizeSp * lineHeightPercent / 100`）/字体/主题即时生效与持久化、跟随系统深浅色、`ReaderViewModel`。**文件来源：经 M1 的 FileOpener 桩读 assets fixtures**（SAF 在 M4 接入）。
- 说明：自定义字体导入（TC-F2-09/10）依赖 SAF 选文件，其实现与验证**推迟到 M4 完成后**一并进行。
- 需求映射：F2.2/F2.3/F2.4（内置字体部分）/F2.5/F2.11/F2.12。
- 验证：TC-F2-01 ~ TC-F2-08、TC-F2-11 ~ TC-F2-13、TC-F2-22/22a；TC-UI-01/02/03（自动化）；TC-F2-24（空文件）。
- DoD：上述用例全部通过；**无障碍基本自检**（按钮有 contentDescription、触摸目标 ≥ 48dp）；TC-UI-01 在 CI 跑通。

### M4 文件访问与首页（2~3d）

- 验证：TC-F1-01 ~ TC-F1-09（手工）；TC-F2-09/10（字体导入）；TC-UT-10（自动化）。
- DoD：F1 全部用例通过；Room 集成验证通过（为 M5 进度表铺路）；TC-F1-09 与 TC-F1-03a 在真机上验证；无障碍基本自检。
