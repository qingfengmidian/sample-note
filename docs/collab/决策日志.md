## D-2026-09-11-02 epub 目录语义：原样呈现，取消生成式兜底

- 背景：原实现按 spine 逐章生成目录条目，无 NCX 匹配时兜底「第 N 章」，导致扉页/出版说明等未编入 NCX 的章节被编造章名。
- 决定：epub 目录 = **文件自带目录原样**（nav.xhtml 优先、NCX 回退；标题/层级/条目数不变）；无目录文件不显示目录入口、不生成任何条目；章节标题无匹配时**留空**（顶栏不显示书名兜底）；目录条目目标 = `file.xhtml#anchor` 的**锚点段落**（容器元素 id → 其内首个段落；未命中 → 章首）；「上一章/下一章」保留按 spine 顺序。
- 理由：目录属文件作者的元数据，应用只做呈现；编造条目会误导阅读定位（真机已证）。锚点段落定位使目录跳转精确到内容。
- 重估条件：若后续要支持 epub 页内链接跳转（V1.3 后规划），锚点映射可复用，届时评估是否扩展。
- 影响范围：`EpubParser`（锚点映射、Document.toc 产出、取消兜底）、`Models.TocEntry`（chapterIndex/anchorParagraph）、M12c 目录面板与顶栏；md 目录语义不变（`paragraphIndex`）。

## D-2026-09-11-03 连续滚动采用「章级渐进物化 + LazyColumn 视窗」而非滑动窗口回收

- 背景：跨章连续滚动需控制渲染与内存；备选方案为「固定窗口回收已读章」。
- 决定：item 列表**只追加、不回收**（当前章 + 预取章渐进物化，`PREFETCH_MARGIN` 触发）；渲染组合上限由 LazyColumn 视窗天然保证；已读章保留（纯文本引用，内存画像 ≈ 现状全量解析）。
- 理由：回收会造成全局 item 索引漂移，进度恢复/目录跳转/位置保持全部要重写，收益仅省纯文本引用内存；解析层本就全量解析，真正的大头（XHTML 字节 → 文本）已在 M11b 由缓存解压与逐章读取控制。记忆：`PagedTextLoader` 的「只 append：索引稳定」契约是既有先例。
- 重估条件：若真机出现长书内存压力（TC-F4-07 回归数据异常），再评估「解析层惰性化」或窗口回收。
- 影响范围：M12b（VM 前缀和/物化状态）、M12c（多章渲染/进度条）；`ProgressEntity` 坐标语义不变（零迁移）。

## D-2026-09-12-03 M12 热修：正文 SVG 内嵌位图提取 + 空章跳过（F4.7 连续滚动断链）

- 背景：真机验收反馈「滑动只能读完一章，无法自动续接下一章」。模拟器复现定案：非「章界卡死」（连滑多章正常），而是《邓小平文选》前 4 个 spine 章为扫描图片页，正文以 `<svg><image xlink:href>` 内嵌位图，EpubParser 不提取 → 解析为 `paragraphs=[] && images=[]` 纯空章：首章空则 items=0、触底追加触发器 `lastVisible>=0` 永不成立 → 打开即白屏滑动无效；书中空章则物化 +0 item、snapshotFlow 不重发 → 断链。
- 决定（两层，简报 `docs/collab/briefs/m12-hotfix-svg-image-empty-chapter.md`）：
  1. **解析层**（F2.14 扩展）：`EpubParser.extractWithPull2` 新增 `<image>` 分支，按 img 同规则提取 svg 内嵌位图（xlink 命名空间优先、裸 href 次之、`.svg` 矢量不提取、owner 归属同 img）；END_TAG 跳过名单加 `image`（自闭合双事件对称，防 pop 坏 svg 帧）。
  2. **VM 层**（F4.7 补洞，防御纵深）：`appendNextChapter` 越过连续空章直达下一非空章；`load()` 恢复/起始章为空章且全书有非空章时前进到其后第一个非空章。`selectChapter`/`onTocJumpToItem`/`ensureMaterialized` 不改（`globalItem(空章,0)` 与 `onFirstVisibleItemChanged` 自愈）。
- 结果：红测试 5 例（3 解析 + 2 VM）→ OpenCode 实现 → Kimi 独立审查 → 全量 **254/0**（1 跳过）。模拟器复验：书名页渲染图片（截图 216KB，白屏基线 23KB；`content-desc="图片"` ×2）、从封面连滑至 1950 年文章无卡无崩溃。
- 审查要点：实现方按 `isNamespaceAware=false` 补齐 `svgImageHref` 的字面 `xlink:href` 兜底（与既有 `innerRasterHref` 同思路）；未改任何红测试断言。
- 影响范围：`EpubParser.kt`、`ReaderViewModel.kt`、`EpubParserTest.kt`、`ReaderViewModelWindowTest.kt`；F2.14 能力扩到 svg 内嵌位图（扫描版 epub 常见）。

## D-2026-09-13-01 F2.17 标题层级：阅读器默认标题层级 + 书 CSS 覆盖语义

- 背景：2026-09-13 用户真机反馈「章节标题（含不同级别标题）与正文看不出字体差异」。根因：F2.15 只应用书自带 CSS 子集，刻意不做阅读器默认标题字号（M11c 审查记为预期边界）；多数书未声明标题字号，《邓小平文选》/Flatland 等标题与正文同字号同字重。需求/规划中无对应条目（§5 后续版本规划亦无），属需求缺口。
- 决定：
  1. **立项 F2.17**（需求 REV9，验收标准 11），排期**独立 M15**（原 M13 配色/M14 双语顺序不变，M15 排其后）。
  2. **范围仅 epub**：md 预览 H4~H6 与正文同字号的问题本次不改（用户明确「只做 epub」），留作后续按需提出。
  3. 解析层按 **XHTML 标签名**记 `Chapter.headingLevels`（与 `paragraphs` 等长、与 `styles` 解耦——标题段无 CSS 命中时仍能取层级）；渲染层在既有合并前插入默认标题层：`fontSize = 全局字号 × headingFactor`（H1 1.6 / H2 1.45 / H3 1.3 / H4 1.2 / H5 1.1 / H6 1.05），默认加粗。
  4. **书 CSS 覆盖而非叠加**：标题段解析出的 `fontSizeEm` 非空 → 以书为准（同属性只保留一个相对倍率，避免 1.6×1.2 双重放大）；`bold` 三态沿用既有语义（null → 默认加粗）。
- 理由：标题层级是纯文本 epub 阅读的基本可读性问题，且与「全局设置为绝对基准 + CSS 相对偏移」的既有框架同层（默认层级只是"无 CSS 时的兜底倍率"），不越「不引入排版引擎」边界；覆盖语义符合作者意图优先，也避免真实书 `h1{font-size:1.5em}` 被放大到 2.4×。
- 重估条件：真机观感若认为档位偏大/偏小，仅调 `headingFactor` 表（设计定稿处标注可微调）；若后续做 md 预览层级补齐或页内链接，可复用同层模型。
- 已知近似：从 `body`/`html` 继承来的字号倍率同样视为「书已声明」而覆盖默认比例（与 M11c 继承模型一致）。
- 影响范围：`docs/需求说明书.md`（REV9）、`docs/软件设计文档.md`（REV11 §3.1/§3.3）、`docs/测试用例.md`（REV7：TC-F2-28/29、TC-UT-17/18、fixtures `headings.epub`）、`docs/开发计划.md`（V1.4 M15）、`FixtureGenerator.kt`、`EpubParser.kt`、`Models.kt`、`ReaderItemAssembly.kt`、`ReaderTextView.kt`。

## D-2026-09-13-02 CSS 候选需求 A/B 暂不立项（外链样式表 / CSS tokenizer）

- 背景：M15 真机走查期间核实两件事——① 本项目 CSS 实现不是 tokenizer，是约 290 行的「字符扫描 + 分隔符切分 + 正则取值」子集匹配器（`EpubParser.kt` `CssSubset`/`parseStyleSheet`），字符串/转义不感知、`@media` 块整体丢弃、`!important` 不参与优先级；② 样式来源只认 `<style>` 块与内联 `style`，**外链 `<link rel="stylesheet">` 与 manifest `.css` 一律不读**——真机书（Flatland 30/30 章、邓小平文选 246/247 章）CSS 全在外链，实际未参与渲染（m12 验收记录中「Calibre CSS 生效」的结论已更正）。
- 候选：**A** = 加载外链样式表并按文档顺序参与层叠（成本低、真实书收益最大，需配套"根级声明策略"避免 `body{text-align:center}`/字号缩放用户设置）；**B** = 按 CSS Syntax L3 做真 tokenizer 并重写块/声明/值扫描（成本中，收益是健壮性：注释/字符串/转义/`;`/`}`/`@media`/`!important`）。
- 决定：**两项均暂不立项**，不改既定排期（继续 M13 弹层配色解耦 → M14 中英双语）。证据与价值分析留档于 `docs/collab/reviews/m15c-acceptance.md` §三（设计边界记录）与本节。
- 理由：当前 `<style>`/内联通道已满足 F2.15 口径（夹具与内联书验证通过）；A 涉及"半套级联"策略决策（真实书 CSS 含 `body` 级对齐/字号声明，处理不当会把书读丑），需要单独立项与真机验证预算；用户判断当前优先做既定里程碑。
- 重估条件：出现「真实书样式明显缺失」的正式反馈（如 Calibre 类书标题/强调全无差异）、或要支持依赖外链 CSS 的排版能力时，先做 A、B 视 A 上线后观感再定。
- 影响范围：无代码改动；`docs/collab/reviews/m15c-acceptance.md`、`docs/软件设计文档.md` §3.2（外链边界已注明）、本日志。

## D-2026-09-13-03 epub 渲染范围边界：以「标题/正文可区分」为目标，不追样式保真

- 背景：M15（F2.17 标题层级）收口时用户补充范围口径——「epub 文档的渲染只需要渲染出章节标题与正文的区别就行了，不需要搞太多复杂的样式」。此前 D-2026-09-13-02 已决定 CSS 候选 A（加载外链样式表）/B（CSS tokenizer）暂不立项，本条把范围口径正式固化到需求与设计。
- 决定：
  1. epub 渲染目标 = **章节标题与正文可区分 + 内容完整可读**；**样式保真非目标**。
  2. F2.15 CSS 子集（字号/字重/斜体/颜色/对齐/段间距/行距）与 F2.17 默认标题层级为**本期终态**：不因个别书的观感追加新 CSS 属性/新选择器，不加载外链样式表。
  3. 不做"无 `h1`~`h6` 标签之书"的标题识别启发式（如按类名/首段长度猜测）——书中未用标签表达层级时，标题与正文可不作区分。
- 理由：真实书里样式表达方式极多样（Calibre 类的 `<p class>`/`<i>` + 外链 CSS 只是其中一种），追保真会滑向排版引擎且回归面大；用户阅读需求以"能分清标题与正文"为准，M15 已满足使用 `h` 标签的书（如《邓小平文选》文章标题、本仓夹具）。
- 重估条件：出现"某类书标题完全无法分辨"的正式反馈且用户要求覆盖时，按 D-2026-09-13-02 的重估路径处理（先 A，后视观感定 B）；届时按新需求条目走 REV/设计/用例流程。

## D-2026-09-18-01 M16 语言切换生效机制：attachBaseContext 包装（全版本）+ LocaleManager（33+），不声明 localeConfig

- 背景：F4.9/M16 要求设置页可切「跟随系统（默认）/ 中文 / 英文」，应用内即时生效并持久化，手动选择优先于系统语言（需求说明书 REV12）。§3.7 在 M14 写明的「本期不提供应用内手动切换」范围注记随本需求解除。真机为 Android 13（SDK 33），33+ 框架路径可直接验证。
- 决定：
  1. **持久值单一来源**：DataStore `app_language` 键存 BCP-47 标签（`zh`/`en`），键缺失或值未知 = 跟随系统；不复用框架态作真值源；`save(ReadingSettings)` 不触碰该键（键级写入，无覆盖风险）。
  2. **生效双路径**：全 API 级在 `MainActivity.attachBaseContext` 按持久值 `createConfigurationContext` 包装（`LocaleSwitcher.wrapBaseContext`）——这是「手动选择优先于系统语言」的落点，且在 OEM 上不依赖框架行为；API 33+ 额外调 `LocaleManager.setApplicationLocales`（`SYSTEM` → 空 `LocaleList`）使框架态与应用态一致，并由系统完成 Activity 重建；API 26~32 由设置页在写入完成后 `Activity.recreate()`；33+ 不手动 recreate（避免与框架重建重复）。框架调用失败静默回退——包装路径已独立保证行为。
  3. **不声明 `android:localeConfig`**：不制造「系统设置 → 按应用语言」这一第二入口，避免与 DataStore 形成双源不一致（系统侧改动不会回写 DataStore）。
  4. 不引 AppCompat、不新增依赖；资源对（values / values-zh）零改动；未覆盖语言回退默认英文由资源回退链保证。
  5. 设置页交互沿用既有 `CycleSettingRow` 循环档位（跟随系统→中文→English→跟随系统），与字号/行距/字体/主题一致，不新增面板/对话框控件。
- 理由：包装路径对全版本行为一致、可被 Robolectric 直接断言（资源取值而非截图），且在 `attachBaseContext` 只同步读一次 DataStore（Activity 构造期，量小）；框架调用仅在 33+ 追加，用于让系统态（多任务卡片、系统设置）与实际显示一致。localeConfig 的收益（系统入口）与双源风险不匹配，本期不做。
- 重估条件：若用户要求「系统设置里也能切本应用语言」，再评估声明 localeConfig 并把系统态纳入真值源（须处理系统侧改动回写 DataStore 的双向同步）。
- 影响范围：新增 `core/settings/LocaleSwitcher.kt`、`core/model/Models.kt`（`AppLanguage`）、`core/settings/SettingsRepository.kt`（键 + flow + 写入）、`MainActivity.kt`（attachBaseContext）、`ui/SettingsScreen.kt`（语言行）、`res/values/strings.xml` 与 `res/values-zh/strings.xml`（键集对等）；新增 `LocaleSwitchTest`/`SettingsLanguageUiTest`（TC-UI-17）、`LocaleSwitchDeviceTest`（TC-UI-18）；`docs/软件设计文档.md`（REV15 §3.7）、`docs/测试用例.md`（REV10）、`docs/开发计划.md`（M16 框定记录）、`docs/collab/briefs/m16-language-switch.md`。
