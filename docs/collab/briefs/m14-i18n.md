## 背景

应用当前所有界面文案为硬编码中文（UI 层 145 处字面量）。目标：全部经 `stringResource()` 外置，默认（英文）资源 `res/values/strings.xml` + 中文 `res/values-zh/strings.xml`，跟随系统语言自动切换，**本期不做应用内手动切换**（禁止引入 AppCompatDelegate.setApplicationLocales）。

应用名已定：默认英文 **Sample Note**、中文**「简记」**（用户命名）。当前 `app_name` 为「简易文档」——由默认英文替换；Manifest `android:label` 已引用 `@string/app_name`，无需改。

## 硬性约束

1. **只许修改**：`app/src/main/`（资源 + Kotlin）、`app/src/test/`、`app/src/androidTest/`。**不得 git 提交/暂存/检出**。
2. **不得修改**新增测试 `LocalizationTest.kt` / `LocalizationDeviceTest.kt` 的任何断言（红测试，随本简报之后由 Kimi 提交）。
3. 既有测试只允许两类适配，**不得弱化断言**：① 因 `ReaderState.error` 类型签名变化产生的**编译性适配**（构造 error 状态处）；② 设备端测试文案断言改经 `context.getString(R.string.xxx)`（Robolectric 测试一律改用 `qualifiers="zh"`，既有中文字面量断言**保持原样**）。解析层断言夹具内容（`标题一`/`第 1 章` 等）一律不动。
4. `ParseException` 的 `message` 构造参数保留中文不动（仅日志可见）；日志、注释、DataStore/Room 内部键不本地化。

### T3 错误文案架构（VM 传类型、UI 映射资源）

- `ReaderState.error: String?` 改为承载错误类型（sealed，如 `ReaderError`：包装 `ParseException` 子类的分支 + `ProviderNotRunning` 单例分支；放 `ui/reader/` 下，签名自定但须让 UI 能 `when` 穷尽）。`ReaderViewModel` 各 catch/分支不再拼中文文案，改为传出错误对象；「文件提供方（如云盘应用）未运行…」现有文案对应 `ProviderNotRunning`。
- Reader UI：error 处 `when(kind)` → `stringResource(R.string.reader_error_*)`。五个 ParseException 子类各一键（UnsupportedFormat/MissingOpf/MalformedContent/TooLarge/NoPermission）；**MalformedContent 展示固定文案，动态 cause 仅日志**。
- Home：`HomeViewModel` 三条一次性提示（「无法访问该文件，已从最近列表移除」「新建文件失败：无法访问所选位置」「无法打开文件：权限不足或文件已被移动/删除」）改传事件类型（sealed/enum），`HomeScreen` snackbar 处映射资源。
- Editor：`EditorViewModel`/`EditorScreen` 的 feedback 对话框与错误 Text 同样类型化 + 资源映射（保存失败/放弃草稿等现有文案逐字入 zh）。
- 展示文案在 zh 下必须与现在**逐字一致**（zh 值沿用），因此 Robolectric 既有断言（已加 zh 限定符）不需改动即可保持绿。
