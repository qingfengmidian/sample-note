# 阅读器 UI 改版设计评审（M10 立项依据）

> 评审日期：2026-09-03  
> 评审人：Kimi Code（架构/UI 设计）  
> 状态：**待用户确认后立项 M10**（本文档仅为设计定稿，不含实现）  
> 关联：`docs/需求说明书.md` REV5（F4.4/F4.5）、`docs/软件设计文档.md` §4/§5、`docs/开发计划.md` M10

## 1. 现状评估

当前阅读器 UI（`ReaderScreen.kt`）结构：

- **顶栏**：返回 + 章节名/书名 + 右上三点菜单（仅 md「预览/源码」与「编辑」两项）。
- **底部工具条**：`Row` + `horizontalScroll` 平铺 5 个文本按钮（自动换行 / A- / A+ / 行距 / 字体 / 主题），epub 再追加 上一章 / 章节 / 下一章，共 8 项需横向滑动才能全部可见。

### 1.1 问题清单（按严重度）

| # | 问题 | 影响 | 用户反馈对应 |
|---|------|------|--------------|
| P1 | 底部工具条横向滑动才能露出 epub 翻章/章节按钮 | 滑动热区紧贴系统手势条（ColorOS 手势导航），**易误触发切换应用/返回桌面**；工具条要求"所见即所得"，不该靠滚动发现功能 | 建议 1 |
| P2 | 排版/字体/主题等**设置类操作平铺在常驻工具条** | 阅读类 App 惯例（微信读书/Kindle/多看）是"沉浸阅读 + 唤起设置面板"，常驻工具条侵占正文高度、视觉上像调试面板 | 建议 1、2 |
| P3 | 三点菜单内容单薄（预览/编辑），承载力浪费 | 设置类入口与文件类入口混杂预期不清 | 建议 2 |
| P4 | 所有操作入口无分组：排版、外观、导航、文件操作平铺同一层级 | 认知负担高，新用户找不到"主题在哪换" | 建议 3 |

### 1.2 现存优点（保留）

- 全部按钮 ≥48dp、有 contentDescription，满足无障碍底线；
- 设置即时生效并持久化（DataStore），行为模型本身正确，**改版只动交互载体，不动状态模型**；
- 章节弹层高亮/缩进/selected 语义、换行切换位置保持（TC-UI-01）等行为已有测试钉死，改版不得回退。

## 2. 改版方案（定稿）

### 2.1 信息架构

```
顶栏（常驻）：
  返回 | 章节名/书名 | [章节图标（epub/md 有 toc 时）] | ⋯ 菜单
    ⋯ 菜单项：预览/源码（md）· 编辑（md/txt，>2MB 置灰附说明）· 阅读设置
正文区：全屏（原底部工具条位置让出，阅读高度 +1 工具条）
阅读设置面板：ModalBottomSheet 分组展示（见 2.2）
章节面板：ModalBottomSheet（原 AlertDialog 升级，保留高亮/缩进语义）
```

### 2.2 阅读设置面板（ModalBottomSheet）

点击 ⋯ →「阅读设置」弹出底部面板，分三组（与 SettingsScreen 全局页同一套数据源，即 F3.3"全局共享"约定不变）：

- **排版**：换行模式（WRAP/NO_WRAP 分段选择或开关）、字号（A- / 当前值 sp / A+）、行距（循环 120/150/180/200%）
- **字体**：代码 / 衬线 / 无衬线 / 自定义 单选
- **主题**：跟随系统 / 默认白 / 护眼绿 / 柔光米黄 / 夜间黑 单选（色块+文字，选中勾）

面板跟随当前阅读主题配色；调节即时生效并持久化（行为不变）；面板可上滑关闭、点遮罩关闭、Esc/返回关闭。

### 2.3 章节导航（epub）

- 顶栏右侧放**章节图标按钮**（`Icons.AutoMirrored.Filled.List`），替代原底部「章节」按钮；md 实现 F2.13 后同位置放「目录」图标。
- 章节面板升级为 ModalBottomSheet，**底部加「上一章 / 下一章」按钮**，替代原底部翻章按钮（面板内翻章后停留在面板可继续选，也可关闭）。
- 移除"epub 左右边缘点击翻章"（设计文档原载）——与长按选择手势冲突区重叠，且无人知晓该隐藏手势；翻章路径统一为面板内按钮。

### 2.4 移除项与不变项

- **移除**：整个底部工具条（`ReaderToolbar`）、底部横向滑动交互。
- **不变**：ViewModel/SettingsRepository 状态模型与全部回调语义；换行切换位置保持、进度上报、章节高亮规则；SettingsScreen 全局设置页继续存在（F4.3），与面板同源。
- **无障碍**：面板与菜单项全部带语义描述；可点击目标 ≥48dp；面板内单选组用 `Modifier.selectable` + stateDescription。

## 3. 改动面估算

| 层 | 改动 |
|---|---|
| `ReaderScreen.kt` | 删 `ReaderToolbar`/`ToolbarButton`；新增 `ReaderSettingsSheet`、`ChapterSheet`（ModalBottomSheet 化）；顶栏加章节图标与「阅读设置」菜单项 |
| ViewModel | **零改动**（回调已齐：toggleWrap/stepFontSize/cycleLineHeight/cycleFont/cycleTheme/selectChapter） |
| 测试 | TC-UI-01~03 驱动 `ReaderContent` 回调的方式不变，预期仅选择器语义微调；新增 TC-UI-06/07（见测试用例.md）；Robolectric 下 ModalBottomSheet 可用 `useUnmergedTree` 断言 |
| 文档 | 需求说明书 REV5（F4.4/F4.5）、设计文档 §4/§5、开发计划 M10 |

## 4. 风险

- ModalBottomSheet 在 Robolectric 语义树中渲染与真机有差异 → 单测只断言面板内控件存在与回调触发，视觉布局以真机验收为准（沿用 M9 惯例）。
- 老用户习惯底部工具条 → v0.0.1 刚发布，用户量仅本机，无迁移成本，改版时机合适。
