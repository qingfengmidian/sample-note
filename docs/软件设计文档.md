## 1. 技术选型

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Kotlin | — |
| UI | Jetpack Compose + Material 3 | 声明式 UI，文本排版与设置界面实现简洁 |
| 架构 | MVVM（ViewModel + StateFlow） | 官方推荐，与 Compose 配合好 |
| minSdk / targetSdk | 26 / 34 | 见需求 2.3 |
| 依赖注入 | 不引入框架，手写简单工厂/单例 | 项目规模小，避免过重 |
| 本地存储 | DataStore（设置） + Room（最近文件、阅读进度） | 均为 Jetpack 官方组件 |
| epub 解析 | 自实现：`java.util.zip` 解 ZIP + `XmlPullParser` 解析 OPF/NCX/nav.xhtml/XHTML | 纯文本提取需求，无需引入完整 epub 库 |
| 编码探测 | juniversalchardet（Mozilla UniversalCharsetDetector 的 Java 移植） | 体积小（约 200 KB），避免"UTF-8 试解失败回退 GBK"的误判 |
| md 渲染 | 自实现简易解析（标题/列表/加粗斜体/代码块） | 预览只读、元素少，可控 |
| 异步 | Kotlin Coroutines + Dispatchers.IO | 文件解析不阻塞 UI |

> 注：md 渲染若后续需求升级，可替换为 `commonmark-java`，解析层接口已预留此可能（见 3.3）。

## 2. 总体架构

分层设计，解析层与 UI 层完全解耦：

```
┌────────────────────────────────────┐
│ UI 层 (Compose)                    │
│  主页/最近文件 · 阅读界面 · 编辑界面 · 设置 │
├────────────────────────────────────┤
│ ViewModel 层 (StateFlow)           │
│  ReaderViewModel · EditorViewModel · HomeViewModel │
├────────────────────────────────────┤
│ 领域/数据层                        │
│  DocumentParser(解析) · DocumentRepository(存取) │
│  SettingsRepository · RecentFilesRepository       │
├────────────────────────────────────┤
│ 平台层                             │
│  SAF/ContentResolver · DataStore · Room           │
└────────────────────────────────────┘
```

## 3. 模块设计

### 3.1 数据模型

```kotlin
/** 统一的文档内存模型：所有格式解析后都归一化为此结构 */
data class Document(
    val uri: String,            // 内容 URI（SAF）
    val name: String,
    val format: DocFormat,      // EPUB / XML / MD / TXT
    val chapters: List<Chapter> // txt/md/xml 为单章；epub 为多章
)

data class Chapter(
    val title: String?,         // 无标题可为 null
    val paragraphs: List<String>// 段落级纯文本，渲染/编辑的基础单位
)

enum class WrapMode { WRAP, NO_WRAP }

/** 字体方案；均不打包字体文件。
 *  CODE 为默认"代码风格"：FontFamily.Monospace，英文/数字走系统等宽字体（编辑器风格），
 *  中文由系统字体回退机制自动落到默认中文字体（各厂商思源黑体系，等线风格）。
 *  等线（DengXian）为微软商业字体，不可随应用分发；需要真等线的用户走 CUSTOM 导入自备 ttf。 */
enum class ReaderFont { CODE, SERIF, SANS, CUSTOM }

/** 阅读主题：前景/背景成对搭配；颜色使用 Compose Color，不用 Long 避免 ARGB 顺序错误 */
enum class ReadingTheme(val background: Color, val foreground: Color) {
    DEFAULT(Color(0xFFFFFFFF), Color(0xFF1B1B1F)),   // 默认白
    EYE_CARE(Color(0xFFC7EDCC), Color(0xFF2B3A2E)),  // 护眼绿（豆沙绿）
    SOFT_LIGHT(Color(0xFFF5F0E1), Color(0xFF3D3A30)),// 柔光米黄（暖黄低亮度）
    NIGHT(Color(0xFF121212), Color(0xFFB8B8B8))      // 夜间黑
}

data class ReadingSettings(
    val fontSizeSp: Int = 16,       // 适中默认值
    val lineHeightMultiplier: Float = 1.5f,
    val wrapMode: WrapMode = WrapMode.WRAP,
    val font: ReaderFont = ReaderFont.CODE, // 默认代码风格，与需求 F2.4 一致
    val theme: ReadingTheme? = null // null = 跟随系统深浅色（浅色→DEFAULT，深色→NIGHT）
)

/** 解析层受控异常，UI 按类型给出差异化提示（需求"稳定性"条目） */
sealed class ParseException(message: String) : Exception(message) {
    class UnsupportedFormat : ParseException("不支持的格式")
    class MissingOpf : ParseException("epub 缺少 OPF 描述文件，无法解析")
    class MalformedContent(cause: Throwable) : ParseException("内容解析失败：${cause.message}")
    class TooLarge : ParseException("文件过大，超出可编辑上限")
    class NoPermission : ParseException("文件访问权限不足或已被移动/删除")
}
```

### 3.2 文档解析层（DocumentParser）

统一接口，按格式分发：

```kotlin
interface DocumentParser {
    /** 全量解析；大文件由实现内部保证分块读取，不在 UI 线程执行；
     *  实现须在循环内调用 ensureActive() 以响应协程取消 */
    suspend fun parse(uri: Uri, resolver: ContentResolver): Document
}

object ParserFactory {
    fun forFormat(format: DocFormat): DocumentParser = when (format) {
        DocFormat.TXT -> TxtParser()
        DocFormat.MD  -> PlainTextParser(DocFormat.MD)
        DocFormat.XML -> PlainTextParser(DocFormat.XML)
        DocFormat.EPUB-> EpubParser()
    }
}
```

- **TxtParser**：编码探测顺序——① BOM 判定 UTF-8/UTF-16LE/BE；② 无 BOM 时读前 8 KB 用 juniversalchardet 探测；③ 探测失败回退 GBK，再兜底 Latin-1。探测结果可用户在阅读界面手动覆盖并即时重载。
- **PlainTextParser**：md/xml 直接按纯文本读入（编码同 TxtParser 逻辑），xml 的高亮在渲染层做，不进解析层。
- **EpubParser**：
  1. `ZipInputStream` 打开 epub，读 `META-INF/container.xml` 定位 OPF，缺失抛 `ParseException.MissingOpf`；
  2. 解析 OPF 的 manifest + spine，得到章节 XHTML 顺序；
  3. 逐个用 `XmlPullParser` 抽取 XHTML 正文文本：遇 `p/h1~h6/li/br` 结束当前段落，丢弃标签与属性，忽略 `img/script/style`；XmlPullParser 自动按 XML 声明处理章节内编码（含非 UTF-8 内嵌 XHTML）；
  4. 章节标题：**优先 epub3**——解析 nav.xhtml（`<nav epub:type="toc">` 内 `<a>` 文本，支持嵌套 `<ol>`）；**不存在则回退 epub2** NCX 的 navLabel；再取不到退化为"第 N 章"。
- 解析在 `Dispatchers.IO` 执行，逐章/逐块循环内 `ensureActive()`：用户返回或切换文件时 ViewModel 的 `viewModelScope` 自动取消未完成解析，避免资源浪费；超过阈值（默认 5 MB）的 txt 只先加载前 N 段，滚动到底部再追加（分块加载，见 F4.2）。

### 3.3 阅读渲染层

- **排版组件 `ReaderTextView`**：基于 Compose 实现。
  - `WRAP` 模式：段落用 `Text` 渲染，宽度充满，自然折行；
  - `NO_WRAP` 模式：每段放入可水平滚动的 `Row`（`horizontalScroll`），`Text` 设 `softWrap = false, maxLines = Int.MAX_VALUE` 按整行绘制；
  - 字号/行距直接来自 `ReadingSettings`，修改后重组即生效；
  - 字体来自 `ReadingSettings.font`，映射规则：`CODE → FontFamily.Monospace`（英文等宽，中文系统自动回退）、`SERIF → FontFamily.Serif`、`SANS → FontFamily.SansSerif`、`CUSTOM → 从导入的字体文件构建 FontFamily`；
  - 阅读主题生效规则：`theme == null` 时跟随系统深浅色（浅色→DEFAULT，深色→NIGHT），否则用所选主题；主题的背景色应用到阅读界面容器与文字底色，前景色应用到正文 `Text`，切换即时重组生效；
  - 正文整体包裹 `SelectionContainer`，支持长按选择并复制（F2.12）。
- **自定义字体导入**：设置页经 SAF 选择 ttf/otf 文件 → 复制到应用私有目录 `files/fonts/` → **导入时立即预验证**：当场用 `Font(file)` 构建 `FontFamily` 并加载 `Typeface`，失败则拒绝导入并提示"字体文件无效"；验证通过才将路径写入 DataStore。运行期加载再失败（文件被删等极端情况）自动回退 `CODE` 并提示。
- **渲染数据流**：`ReaderViewModel` 持有 `Document` + 当前章节索引 + `ReadingSettings`，向 UI 暴露单个 `StateFlow<ReaderUiState>`。
- **换行模式切换**：切换前记录当前首个可见段落索引与段内偏移，切换后滚动回该段落（F2.2 的"尽量保持位置"）。
- **阅读进度**：`(uri, chapterIndex, firstVisibleParagraph)` 退出时写入 Room，重开时恢复。
- **md 预览**：`MarkdownRenderer` 将段落流映射为标题/列表/引用/代码块等 Compose 组件，仅覆盖基本语法；接口独立，后续可换成 commonmark 实现。
- **xml 高亮（可选，低优先级）**：渲染层按正则对标签/属性/文本着色，不影响解析层。

### 3.4 编辑器

- 编辑组件：Compose `BasicTextField` + 自定义 `VisualTransformation`（md 可选简单着色，txt 不着色）。
- `EditorViewModel`：
  - 持有 `TextFieldValue` 与 `dirty` 标记；撤销/重做使用 `TextFieldValue` 历史栈（限制 100 步）。
  - 保存：将文本按 UTF-8 经 `ContentResolver.openOutputStream(uri, "wt")` 写回 SAF 文件；写前校验 `dirty`。**部分 SAF Provider 不支持 `"wt"` 截断模式**：捕获 `FileNotFoundException`/`UnsupportedOperationException` 后回退为 `"w"` 模式重写，仍失败则提示用户另存。
  - 退出拦截：`onBackPressed` 检查 `dirty`，弹出"保存/放弃/取消"对话框（F3.2）。
  - 自动保存（F3.4）：`snapshotFlow` 监听内容，`debounce(3s)` 落盘，默认关闭。
  - **进程死亡恢复**：编辑文本、光标位置与 `dirty` 经 `SavedStateHandle` 持久化，进程被杀重建后恢复到编辑现场。
- 字号/行距/字体/主题：编辑器样式读取同一 `ReadingSettings`，编辑区背景/前景色与阅读界面一致（F3.3，全局共享一套设置，不按文件独立存储）。

### 3.5 仓库与持久化

| 仓库 | 职责 | 存储 |
| --- | --- | --- |
| `SettingsRepository` | 默认字号、行距、换行模式、字体（含自定义字体文件路径）、阅读主题、md 自动保存开关 | DataStore Preferences |
| `RecentFilesRepository` | 最近打开列表（去重、上限 50 条、置顶最新） | Room 表 `recent_file(uri, name, format, opened_at)` |
| `ProgressRepository` | 阅读进度 | Room 表 `reading_progress(uri, chapter, paragraph)` |
| `DocumentRepository` | 按 URI 调解析层得到 `Document`；md/txt 的读/写文本 | ContentResolver + ParserFactory |

### 3.6 文件访问与权限

- 打开文件一律走 SAF：`ActivityResultContracts.OpenDocument()`（mimeType 限定 `text/*`、`application/epub+zip` 等），并对返回 URI 调用 `takePersistableUriPermission` 以支持"最近打开"再次访问。
- 接收"打开方式"：Manifest 注册 `ACTION_VIEW` intent-filter（上述 mimeType + `file`/`content` scheme）。
- 不申请任何存储运行时权限，天然兼容 scoped storage。

## 4. 界面与导航

单 Activity + Compose Navigation：

```
HomeScreen ──打开──▶ ReaderScreen ──切换──▶ EditorScreen (仅 md/txt)
    │                    │
    └──▶ SettingsScreen  └──▶ ChapterListSheet (仅 epub)
```

- **HomeScreen**：最近文件列表 + "打开文件"按钮。
- **ReaderScreen**：顶部栏（书名/章节名、菜单）；正文区；底部工具条（换行模式切换、字号 A-/A+、行距、字体、阅读主题、章节列表）。epub 左右边缘点击或底部按钮翻章节。
- **EditorScreen**：顶部栏（文件名、保存按钮、撤销/重做）；全屏编辑区。

## 5. 关键流程

### 5.1 打开 epub 并阅读

```
用户选文件 → SAF 返回 URI → DocumentRepository 识别格式(EPUB)
→ EpubParser 解析(后台, 显示加载圈, 可被取消) → 得到 Document(多章)
→ 查 ProgressRepository 恢复上次章节/段落 → ReaderTextView 渲染
→ 用户切 NO_WRAP → 记录当前段落索引 → 以 no-wrap 重组 → 滚动回原段落
```

### 5.2 编辑并保存 txt

```
ReaderScreen 点"编辑" → EditorScreen 载入全文文本
→ 用户修改(dirty=true) → 点保存 → openOutputStream("wt") 写回
   (Provider 不支持 "wt" 时回退 "w" 重写)
→ 保存成功清 dirty → 返回阅读界面按新内容重新解析显示
```

## 6. 非功能设计要点

- **性能**：解析全部在 IO 协程；大文本分块加载（首屏 200 段，滚动到底部阈值时预取下一块，预取窗口保持前后各 200 段）；长列表用 `LazyColumn` 按段落懒渲染，避免一次性排版整本书。
- **稳定性**：解析失败按 `ParseException` 子类型差异化提示（格式不支持 / 缺少 OPF / 内容损坏 / 文件过大 / 权限不足），不统一报"文件损坏"；OOM 单独捕获并提示"文件过大"。
- **配置变更**：ViewModel 持有全部状态，横竖屏切换/深色模式切换不丢内容与位置；编辑器另经 `SavedStateHandle` 覆盖进程死亡场景。
- **无障碍**：主题前景/背景对比度 ≥ 4.5:1（四套预设主题均满足）；交互控件 ≥ 48dp；按钮带 `contentDescription` 支持 TalkBack。
- **混淆/发布**：release 开启 R8；epub/XML 解析仅用 JDK 与 Android 自带 API，juniversalchardet 需加 `-keep` 规则（其内部按类名反射加载探测器）。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 非标准 epub（缺导航文件、XHTML 不规范） | 导航按 epub3 nav.xhtml → epub2 NCX → "第 N 章" 逐级降级；XHTML 解析失败时退化为"剥标签"正则提取，保证有内容可读 |
| 编码误判 | juniversalchardet 探测 + BOM 优先；仍误判时允许用户在阅读界面手动切换编码并即时重载 |
| SAF Provider 不支持 `"wt"` 截断 | 回退 `"w"` 模式重写；仍失败提示另存 |
| SAF 持久权限失效（文件被移动/删除） | 打开时捕获 `SecurityException`，提示并移出最近列表 |
| 超大 txt（几十 MB）编辑卡顿 | 编辑全量加载设上限（默认 10 MB 可编辑，超出提示只读打开） |
