## 1. 技术选型

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Kotlin | — |
| UI | Jetpack Compose + Material 3 | 声明式 UI，文本排版与设置界面实现简洁 |
| 架构 | MVVM（ViewModel + StateFlow） | 官方推荐，与 Compose 配合好 |
| minSdk / targetSdk | 26 / 34 | 见需求 2.3 |
| 依赖注入 | 不引入框架，手写简单工厂/单例 | 项目规模小，避免过重 |
| 本地存储 | DataStore（设置） + Room（最近文件、阅读进度） | 均为 Jetpack 官方组件 |
| epub 解析 | 自实现：`java.util.zip` 解 ZIP + `XmlPullParser` 解析 OPF/NCX/nav.xhtml/XHTML | 纯文本提取需求，无需引入完整 epub 库 |
| 编码探测 | 严格解码级联：BOM → 严格 UTF-8 判定 → 严格 GBK → Latin-1 | 零第三方依赖；原选型 `android.icu.text.CharsetDetector` 非公开 SDK 类，真机 hidden API 拦截（M3 真机验证推翻） |
| md 渲染 | 自实现简易解析（标题/列表/加粗斜体/代码块） | 预览只读、元素少，可控 |
| 异步 | Kotlin Coroutines + Dispatchers.IO | 文件解析不阻塞 UI |

> 注：md 渲染若后续需求升级，可替换为 `commonmark-java`，解析层接口已预留此可能（见 3.3）。

## 2. 总体架构

分层设计，解析层与 UI 层完全解耦：

```
┌────────────────────────────────────┐
│ UI 层 (Compose)                    │
│  主页/最近文件 · 阅读界面 · 编辑界面 · 设置 │
├────────────────────────────────────┤
│ ViewModel 层 (StateFlow)           │
│  ReaderViewModel · EditorViewModel · HomeViewModel │
├────────────────────────────────────┤
│ 领域/数据层                        │
│  DocumentParser(解析) · DocumentRepository(存取) │
│  SettingsRepository · RecentFilesRepository       │
├────────────────────────────────────┤
│ 平台层                             │
│  SAF/ContentResolver · DataStore · Room           │
└────────────────────────────────────┘
```

## 3. 模块设计

### 3.1 数据模型

```kotlin
enum class DocFormat { EPUB, XML, MD, TXT }

/** 统一的文档内存模型：所有格式解析后都归一化为此结构 */
data class Document(
    val uri: String,            // 内容 URI（SAF）
    val name: String,
    val format: DocFormat,
    val chapters: List<Chapter>, // txt/md/xml 为单章；epub 为多章
    val toc: List<TocEntry> = emptyList() // 文档目录（F2.13/F2.16）：md 由标题提取；epub 自 M12 起产出文件自带目录（nav/NCX 原样，见 §3.8），无目录文件为空
)

data class Chapter(
    val title: String?,         // 无标题可为 null
    val paragraphs: List<String>,// 段落级纯文本，渲染/编辑/进度/toc 的基础单位（LazyColumn item 索引 == 段落索引，恒成立）
    val level: Int = 1,          // 章节层级（1 起）：epub 目录嵌套用于章节列表缩进，单章格式恒为 1
    val images: List<ParagraphImage> = emptyList(),  // 图片（F2.14，仅 epub 非空；M11 待实施）：挂所属段落 item 内渲染，
                                  // 不新增 LazyColumn 项——段落索引稳定，进度恢复/toc 锚定/换行位置保持零改动（评审 S8）
    val styles: Map<Int, ParagraphStyleHints> = emptyMap(), // CSS 样式提示（F2.15，仅 epub 非空）：段落索引 → 相对样式
    val headingLevels: List<Int?> = emptyList() // F2.17（M15 待实施）：与 paragraphs 等长、按段落索引对齐的标题层级
                                  // （1~6 = h1~h6；null = 非标题）；仅 epub 非空。与 styles 解耦——
                                  // 标题段无任何 CSS 命中（styles 无该索引）时渲染层仍能取到层级走默认标题样式
)

/** 段落内图片（F2.14，M11 待实施）：src 为 epub zip 内路径（manifest href 规范化）；svg 不直接渲染（渲染层给占位） */
data class ParagraphImage(
    val paragraphIndex: Int,     // 所属段落索引：图片渲染在该段落 item 内（文字下方；封面在首段文字上方）
    val src: String,
    val alt: String? = null,     // 无障碍语义描述来源；占位提示优先显示 alt
    val isCover: Boolean = false // 封面图（OPF cover 声明）：挂 paragraphIndex=0，按屏宽置顶渲染
)

/** CSS 子集相对样式提示（F2.15，仅 epub 非空）：全部为"相对全局设置的偏移/开关"，渲染层负责合并。
 *  三态字段语义：null = 未指定（走全局）；显式 false 可压过继承（如 <style> 继承粗 + 内联 font-weight:normal → 非粗）。 */
data class ParagraphStyleHints(
    val fontSizeEm: Float? = null,   // 相对字号倍率（如 1.2f），渲染时 clamp 0.5~3.0 后乘全局字号
    val lineHeightEm: Float? = null, // 相对行距倍率，同上 clamp
    val bold: Boolean? = null,       // null 未指定；true 加粗 / false 非粗（font-weight ≥600/bold/bolder→true）
    val italic: Boolean? = null,     // null 未指定；true 斜体（font-style: italic/oblique）/ false 非斜
    val textAlign: Int? = null,      // 0 左 1 中 2 右（text-align 子集）；null 未指定
    val colorArgb: Int? = null,      // CSS 颜色（Int 存 ARGB，alpha=FF 不透明）；对比度 <4.5:1 由渲染层回退主题前景色
    val paragraphSpacing: Boolean = false // margin/padding 垂直分量 0/非 0 两档段距（true = 非 0，item 间加段距）
)

/** 目录锚点（F2.13，M11 待实施）：md 的标题 → 段落索引；锚定单章段落流，滚动目标即 paragraphIndex */
data class TocEntry(
    val level: Int,            // 1~6（对应 H1~H6）
    val title: String,         // 标题纯文本（去除 # 前缀与行内标记符号；F2.13 REV8：链接剥为链接文字）
    val paragraphIndex: Int,   // 标题所在段落索引（md 单章语义；epub 恒 0，见下）
    val chapterIndex: Int = 0,     // F2.16：目标章（spine 序）；md 恒 0
    val anchorParagraph: Int? = null // F2.16：epub 锚点段落（目录条目 href 的 #fragment 映射）；md 用 paragraphIndex
)

enum class WrapMode { WRAP, NO_WRAP }

/** 字体方案；均不打包字体文件。
 *  CODE 为默认"代码风格"：FontFamily.Monospace，英文/数字走系统等宽字体（编辑器风格），
 *  中文由系统字体回退机制自动落到默认中文字体（各厂商思源黑体系，等线风格）。
 *  等线（DengXian）为微软商业字体，不可随应用分发；需要真等线的用户走 CUSTOM 导入自备 ttf。 */
enum class ReaderFont { CODE, SERIF, SANS, CUSTOM }

/** 阅读主题：前景/背景成对搭配；颜色使用 Compose Color，不用 Long 避免 ARGB 顺序错误 */
enum class ReadingTheme(val background: Color, val foreground: Color) {
    DEFAULT(Color(0xFFFAFAFA), Color(0xFF1B1B1F)),   // 默认白（微淡灰白，降低 OLED 亮度冲击）
    EYE_CARE(Color(0xFFC7EDCC), Color(0xFF2B3A2E)),  // 护眼绿（豆沙绿）
    SOFT_LIGHT(Color(0xFFF5F0E1), Color(0xFF3D3A30)),// 柔光米黄（暖黄低亮度）
    NIGHT(Color(0xFF121212), Color(0xFFB8B8B8))      // 夜间黑
}

data class ReadingSettings(
    val fontSizeSp: Int = 16,          // 适中默认值
    val lineHeightPercent: Int = 150,  // 行距以 Int 百分值存储（150 = 1.5 倍），避免 Float 读写精度问题；档位 120/150/180/200
    val wrapMode: WrapMode = WrapMode.WRAP,
    val font: ReaderFont = ReaderFont.CODE, // 默认代码风格，与需求 F2.4 一致
    val theme: ReadingTheme? = null    // null = 跟随系统深浅色（浅色→DEFAULT，深色→NIGHT）
)

/** 解析层受控异常，UI 按类型给出差异化提示（需求"稳定性"条目） */
sealed class ParseException(message: String) : Exception(message) {
    class UnsupportedFormat : ParseException("不支持的格式")
    class MissingOpf : ParseException("epub 缺少 OPF 描述文件，无法解析")
    class MalformedContent(cause: Throwable) :
        ParseException("内容解析失败：${cause.message ?: cause::class.simpleName}")
    class TooLarge : ParseException("文件过大，超出可编辑上限")
    class NoPermission : ParseException("文件访问权限不足或已被移动/删除")
}
```

### 3.2 文档解析层（DocumentParser）

统一接口，按格式分发：

```kotlin
interface DocumentParser {
    /** 全量解析；大文件由实现内部保证分块读取，不在 UI 线程执行；
     *  实现须在循环内调用 ensureActive() 以响应协程取消 */
    suspend fun parse(uri: Uri, resolver: ContentResolver): Document
}

object ParserFactory {
    fun forFormat(format: DocFormat): DocumentParser = when (format) {
        DocFormat.TXT -> TxtParser()
        DocFormat.MD  -> PlainTextParser(DocFormat.MD)
        DocFormat.XML -> PlainTextParser(DocFormat.XML)
        DocFormat.EPUB-> EpubParser()
    }
}
```

- **TxtParser**：编码探测顺序——① BOM 判定 UTF-8/UTF-16LE/BE；② 无 BOM 时读前 8 KB 做**严格 UTF-8 解码判定**（尾部 ≤3 字节的不完整多字节字符回退重试）；③ 失败依次回退 GBK（严格解码）→ Latin-1。探测结果可由用户在阅读界面手动覆盖并即时重载。（原方案"平台 `android.icu.text.CharsetDetector` + 置信度 < 50 阈值"在 M3 真机验证中被推翻：该类不在公开 SDK，hidden API 策略拦截反射调用，探测恒失败。）
- **PlainTextParser**：md/xml 直接按纯文本读入（编码同 TxtParser 逻辑），xml 的高亮在渲染层做，不进解析层。**md 额外提取目录（F2.13，M11 待实施）**：与 `MarkdownParser` 共用同一标题扫描函数（防两版逻辑漂移，评审 S10），复用标题语法（`^#{1,6}\s+`）逐段扫描；**仅支持 ATX 形式，不支持 ATX 封闭（`# 标题 #`）与 Setext（`===`/`---`）标题**；生成 `Document.toc`（`TocEntry(level, title, paragraphIndex)`，锚定单章段落流中标题所在段落索引）；**`` ``` `` 围栏代码块内的行一律跳过**，避免把代码注释误判为标题；标题文本去除 `#` 前缀与行内标记（加粗/斜体/行内代码符号），取纯文本；无标题文档 toc 为空；全量解析中单次线性扫描完成，无额外 IO。
- **EpubParser**：
  1. `ZipInputStream` 打开 epub，读 `META-INF/container.xml` 定位 OPF，缺失抛 `ParseException.MissingOpf`；
  2. 解析 OPF 的 manifest + spine，得到章节 XHTML 顺序；
  3. 逐个用 `XmlPullParser` 抽取 XHTML 正文（F2.14/F2.15，**M11 待实施**——届时不再忽略 img/style，改为保留信息）：遇 `p/h1~h6/li/br` 结束当前段落；块级 `<img>` 生成 `ParagraphImage` 挂到**当前段落索引**（同行内 img 取所在段落），src 取 manifest 规范化 zip 路径，alt 取 @alt，svg 保留 src 由渲染层占位；`<style>` 与内联 `style` 属性按 CSS 子集规则解析为 `ParagraphStyleHints` 记入 `Chapter.styles[段落索引]`（F2.15，见下）；**外链样式表不加载**——`<link rel="stylesheet" href="...">` 与 OPF manifest 中的 `.css` 文件一律不读取，样式来源仅限 `<style>` 块与内联 `style` 属性（范围边界；真机常见书如 Calibre 产出的 Flatland、邓小平文选 CSS 全在外链文件，实际按全局设置渲染，2026-09-13 核实）；`script` 仍忽略；章节内编码采取**防御性处理**——优先信任 XML 声明（epub 规范要求 UTF-8/UTF-16），**`XmlPullParser` 抛出 `XmlPullParserException` 时回退按 UTF-8 重新解析一次**；CSS 子集解析失败不抛异常，该书该章回退纯文本渲染（保底可读）；
  4. 章节标题：**优先 epub3**——解析 nav.xhtml（`<nav epub:type="toc">` 内 `<a>` 文本，支持嵌套 `<ol>`）；**不存在则回退 epub2** NCX 的 navLabel；再取不到退化为"第 N 章"。
  5. **图片随机访问（F2.14，M11 待实施）**：SAF `content://` 流不支持随机读，而图片需懒加载——打开 epub 时将其**一次性解压到应用私有缓存 `cache/epub/<uri md5 前16位>/`**（解析与渲染均从缓存目录读，原 zip 流即关；容量 ≤ 原书大小，进入下一本书/缓存超限按单实例 LRU 清理）。封面识别：OPF `<meta name="cover" content="{id}">` 或 manifest `properties="cover-image"`，生成 `isCover=true, paragraphIndex=0` 的 `ParagraphImage`（渲染于首段文字上方）；svg 封面仅当内嵌位图引用时提取，纯矢量 svg 不渲染。
  6. **CSS 子集（F2.15，M11 待实施）**：支持的选择器——元素、`element.class`、`.class`、`#id`（后代/组合选择器忽略）；支持的属性——`font-size`（px/pt/em/%，em/% 转倍率，px/pt 按 16sp 基准转倍率）、`line-height`（同 font-size 规则）、`font-weight`（≥600 或 bold/bolder → bold）、`font-style: italic/oblique`、`text-align`（left/center/right）、`color`（#rgb/#rrggbb/rgb() 命名色子集）、`margin/padding` 垂直分量（转段间距，仅 0 与非 0 两档，不做精确排版）。继承模型：块级元素样式沿 DOM 树向子代继承，内联 `style` 优先级最高，`<style>` 规则按"后定义覆盖先定义、id > class > 元素"合并；一切未识别属性/选择器静默忽略。
- 解析在 `Dispatchers.IO` 执行，逐章/逐块循环内 `ensureActive()`：用户返回或切换文件时 ViewModel 的 `viewModelScope` 自动取消未完成解析，避免资源浪费；**txt 一律走分块加载（M8b 定稿，F4.2）**：`PagedTextLoader` 流式逐段泵出，首块 200 段即上屏，滚动接近底部（余量 50 段）追加下一块；段落序列与 `String.lines()` 完全一致（含末尾空段语义），编码探测沿用头部 ≤8 KB 级联（流式解码用 REPLACE，不做全文严格回退——与全量路径在"头 8 KB 可解、后段损坏"的极端样本上存在已知偏差，可接受）。md/xml/epub 维持全量解析。

### 3.3 阅读渲染层

- **排版组件 `ReaderTextView`**：基于 Compose 实现。
  - `WRAP` 模式：段落用 `Text` 渲染，宽度充满，自然折行；
  - `NO_WRAP` 模式：每段放入可水平滚动的 `Row`（`horizontalScroll`），`Text` 设 `softWrap = false, maxLines = Int.MAX_VALUE` 按整行绘制；
  - 字号/行距直接来自 `ReadingSettings`，行距换算公式：`lineHeight = (fontSizeSp * lineHeightPercent / 100).sp`，修改后重组即生效；
  - 字体来自 `ReadingSettings.font`，映射规则：`CODE → FontFamily.Monospace`（英文等宽，中文系统自动回退）、`SERIF → FontFamily.Serif`、`SANS → FontFamily.SansSerif`、`CUSTOM → 从导入的字体文件构建 FontFamily`；
  - 阅读主题生效规则：`theme == null` 时跟随系统深浅色（浅色→DEFAULT，深色→NIGHT），否则用所选主题；主题的背景色应用到阅读界面容器与文字底色，前景色应用到正文 `Text`，切换即时重组生效；
  - 正文整体包裹 `SelectionContainer`，支持长按选择并复制（F2.12）。
- **自定义字体导入**：设置页经 SAF 选择 ttf/otf 文件 → 以 UUID 重命名后复制到应用私有目录 `files/fonts/`（避免同名冲突）→ **导入时立即预验证**：当场用 `Font(file)` 构建 `FontFamily` 并加载 `Typeface`，失败则删除副本、拒绝导入并提示"字体文件无效"；验证通过才将路径写入 DataStore。运行期加载再失败（文件被删等极端情况）自动回退 `CODE` 并提示。
- **渲染数据流**：`ReaderViewModel` 持有 `Document` + 当前章节索引 + `ReadingSettings`，向 UI 暴露单个 `StateFlow<ReaderUiState>`。
- **换行模式切换**：切换前记录当前首个可见段落索引与段内偏移，切换后滚动回该段落（F2.2 的"尽量保持位置"）。
- **阅读进度**：`(uri, chapterIndex, firstVisibleParagraph)` 随首可见段落变化即写入 Room（500ms 防抖，一致性评审 G4——比"退出时写入"更防丢），重开时恢复。
- **md 预览**：`MarkdownRenderer` 将段落流映射为标题/列表/引用/代码块等 Compose 组件，仅覆盖基本语法；接口独立，后续可换成 commonmark 实现。
- **md 目录（F2.13，M11 待实施）**：顶栏「目录」图标按钮（与 epub「章节」同位置，F4.5），`Document.toc` 为空时隐藏；目录底部弹层复用章节面板交互模式——按 `level` 缩进、当前标题高亮、`selected` 语义、点击目标 ≥ 48dp。**跳转目标为段落索引**：源码视图（LazyColumn item 即段落）直接滚动到 `paragraphIndex`；预览视图（item 为 MarkdownBlock，索引与段落不同义）经「MarkdownBlock ↔ 段落起始索引」映射换算后再滚动——`MarkdownBlock` 带 `startParagraphIndex` 字段（解析时按"块起始行在段落流中的行号"记录；CodeBlock 锚定其围栏起始行，空行按段落切分规则计数），正向取所属目录项、反向经该字段换算回段落索引（评审 S4）。滚动完成后由现有 `snapshotFlow(firstVisibleItemIndex)` 上报机制自然持久化阅读进度（F2.8），无需新增进度字段；**预览视图经目录跳转后按反向映射得到的段落索引上报进度（评审 S3 方案①），预览模式下的普通滚动仍不上报**。当前标题高亮：源码视图取首个可见段落所属的目录项，预览视图按块映射后取所属目录项；**首可见段落位于第一个目录标题之前时无高亮项**（评审 S11，不显式高亮）。
- **md 表格渲染（F2.18，M20，§3.3）**：`MarkdownBlock` 新增 `Table(header: List<List<MdInline>>, aligns: List<MdAlign>, rows: List<List<List<MdInline>>>, startParagraphIndex)` 与 `MdAlign{LEFT,CENTER,RIGHT}`。识别严格 GFM 管道表语义：**表头行 + 分隔行必需**（缺分隔行的竖线文本按普通段落原文输出），分隔行 `|?-+|?` 单元格含可选冒号（`:---` 左/`:--:` 中/`---:` 右，无冒号左）；支持省略首尾竖线、`\|` 转义（不当分隔符、转义符剥除）、单元格 trim 后过 `parseInline`（加粗/斜体/行内代码生效）；表体吞行截止于空行/块起始语法（`#`/`>`/列表）/无未转义竖线；行数不齐按表头列数补空单元格/截断（R1）；围栏代码块内不识别；`startParagraphIndex` 锚定表头行（U4 块↔段落映射与目录坐标零改动）；表体吞行循环查线程中断位（非挂起路径，同 `scanHeadings` 约定）。渲染组件 `MdTable`：Column 包 Row（表头 + 表体），单元格走既有行内渲染路径，字号/字体/颜色沿用预览 `base` TextStyle（零硬编码颜色）；表头加粗 + 底部分隔线（前景 α=0.28）、表体行间更浅分隔线（α=0.14）；列宽 `max(96dp, 可用宽/列数)` 各行共享（R2 等宽拍板），总宽超屏容器 `horizontalScroll` 且与 LazyColumn 垂直滚动互不抢占；长按选择复制复用外层 `SelectionContainer`（R3，不新造交互）；容器 `semantics` 描述行列数（`reader_table_semantics` 中英双语键）；语义测试接缝 `MdTableCellBoldKey`/`MdTableCellAlignKey`/`MdTableHorizontalScrollKey`。**已知取舍（M21 已解决）**：长文列与短列等宽导致高行/多折行——M21（REV20）已改为按内容占比自适应（单列上限 50% 可用宽），触顶 CAP 时表格不撑满屏宽（余量不可回收）为残余取舍。
- **epub 富文本渲染（F2.14/F2.15，M11 待实施）**：
  - **挂载规则（评审 S8）**：图片与样式**不新增 LazyColumn 项**——`ParagraphImage` 渲染在所属段落 item 内（文字下方；封面 `isCover` 在首段文字上方），`styles[索引]` 只影响该段落 `Text` 的 `TextStyle`。LazyColumn item 索引 == 段落索引恒成立，进度上报（F2.8）、toc 锚定（F2.13）、换行切换位置保持（TC-UI-01）零改动；txt/md/xml 两字段恒空，渲染路径与旧版一致。
  - **图片管线（零第三方依赖）**：`BitmapFactory.decodeFile` + `inSampleSize` 按屏宽 2 倍目标采样（防大图 OOM）；decode 全在 `Dispatchers.IO`，块不可见即不触发（LazyColumn 天然懒加载）；解码失败/文件缺失/svg 统一渲染**占位提示**（主题前景色图标 + "图片无法显示"文字，alt 非空显示 alt，占位与图片均带 contentDescription/语义描述，评审 S9），不崩溃、不阻塞正文。
  - **封面**：`isCover=true` 按屏宽等比渲染于第一章首段上方，高度自适应，不参与段落索引。
  - **样式合并规则（F2.15 与全局设置的优先级）**：全局设置（字号/行距/字体/主题）为**绝对基准**；CSS 仅产生相对偏移——`fontSizeEm/lineHeightEm` clamp 0.5~3.0 后乘全局值，`bold/italic/textAlign` 直接采用；`colorArgb` 与当前主题背景计算对比度，**不足 4.5:1 一律回退主题前景色**（无障碍硬要求）；段间距只做 0/非 0 两档。任何属性解析失败静默忽略，单段失败回退全局默认样式，整书不因样式解析失败而不可读。
  - **标题层级默认（F2.17，仅 epub `h1`~`h6` 段，M15 待实施）**：在上述合并之前插入一层**阅读器默认标题样式**——`fontSize = 全局字号 × headingFactor(level)`，`headingFactor` = H1 1.6 / H2 1.45 / H3 1.3 / H4 1.2 / H5 1.1 / H6 1.05（逐级递减，档位为设计定稿、真机观感可微调），`bold` 默认 `true`；层级判定按 **XHTML 标签名**（`h1`~`h6`，解析层记入 `Chapter.headingLevels[段落索引]`），`p/li/div` 等非标题段不受影响。**书 CSS 优先（覆盖而非叠加）**：该标题段解析出的 `fontSizeEm` 非空则以书为准（同属性只保留一个相对倍率，避免 1.6×1.2 双重放大），`bold` 三态保持既有语义（null → 用默认加粗；显式 true/false → 遵循书）。行距/字体/段距/对比度回退沿用既有规则不变；无标题书零影响（`headingLevels` 全 null 走原路径）。已知近似：从祖先（`body`/`html`）继承来的字号倍率同样视为「书已声明」而覆盖默认比例（与 M11c 继承模型一致，记录备查）。渲染层数据通路：`assembleReaderItems` 把 `headingLevels[段落]` 挂到 `ReaderItem`（不新增 LazyColumn 项，索引契约不变）。
  - **选择复制**：`SelectionContainer` 包段落 item 即可（图片不参与选择，F2.12 语义不变）；epub 只读，无编辑适配问题。
- **xml 高亮（可选，低优先级）**：渲染层按正则对标签/属性/文本着色，不影响解析层。

### 3.4 编辑器

- 编辑组件：Compose `BasicTextField` + 自定义 `VisualTransformation`（md 可选简单着色，txt 不着色）。
- `EditorViewModel`：
  - 持有 `TextFieldValue` 与 `dirty` 标记；撤销/重做使用 `TextFieldValue` 历史栈（限制 100 步）。
  - 保存（**先写临时文件，再一次写回**）：① 将文本按 UTF-8 写入应用缓存目录临时文件并校验字节完整性；② 经 `ContentResolver.openOutputStream(uri, "wt")` 从临时文件一次性写回 SAF；③ 部分 Provider 不支持 `"wt"` 截断模式，捕获 `FileNotFoundException`/`UnsupportedOperationException` 后回退 `"w"` 模式重写（S1 实测：Drive 上 `"wt"`/`"w"` 均支持且正确截断）；④ 仍失败则提示用户另存（临时文件保留，不丢内容）。写前校验 `dirty`。**注意**：若异常为 `FileNotFoundException: No content provider`，说明云盘 Provider 进程被 OEM 杀死而非权限丢失（S1 实测），提示用户启动对应应用后重试，不得按权限失效处理。
  - 退出拦截：`onBackPressed` 检查 `dirty`，弹出"保存/放弃/取消"对话框（F3.2）。
  - 自动保存（F3.4）：`snapshotFlow` 监听内容，`debounce(3s)` 落盘，默认关闭。
  - **进程死亡恢复（草稿恢复文件方案）**：`SavedStateHandle` **只存轻量状态**（`uri`、光标位置、`dirty`），不存正文——避免 `Bundle` 约 1 MB 事务上限导致 `TransactionTooLargeException`。编辑草稿在内容变化时防抖（1 s）写入应用私有目录 `files/edit_recovery/<md5(uri).take(16)>.draft`（**哈希算法固定为 MD5 取前 16 字符**，确定性、避免超长 URI 文件名），进程被杀重建后从草稿文件恢复编辑现场。**该方案对文本大小无上限**（覆盖当前 2 MB 编辑上限；真机 5MB 全量 TextField 触发 ANR，故上限由设计 10 MB 下调为 2 MB）。
  - **草稿清理策略**：① 保存成功或用户选择"放弃"时删除对应草稿；② 最近文件列表条目被移除/清空时同步删除对应草稿；③ 应用启动时遍历 `edit_recovery/`，删除创建时间超过 7 天的孤儿草稿。
- 字号/行距/字体/主题：编辑器样式读取同一 `ReadingSettings`，编辑区背景/前景色与阅读界面一致（F3.3，全局共享一套设置，不按文件独立存储）。**换行模式（WRAP/NO_WRAP）不作用于编辑器**——编辑器始终软换行（一致性评审 U5，F3.3 字面歧义在此澄清）。
- **行尾与编码约定（一致性评审 C2）**：编辑载入经 `lines()` 拆分、保存统一按 UTF-8 + LF 行尾写回——GBK 文件保存后转为 UTF-8，CRLF 文件转为 LF；此为既定设计（"记事本式"工具，不承诺保原字节/原编码），载入显示的编码探测不受影响。

### 3.6 文件访问与权限

- 打开文件一律走 SAF：`ActivityResultContracts.OpenDocument()`。MIME 限定 `text/*`、`application/epub+zip`，并**附加 `*/*` 回退**——部分文件管理器把 epub 返回为 `application/octet-stream`，此时由应用按扩展名与文件头（ZIP magic + `mimetype` 条目）自行嗅探判定。
- 接收"打开方式"：Manifest 注册 `ACTION_VIEW` intent-filter（上述 mimeType + `file`/`content` scheme）。
- 不申请任何存储运行时权限，天然兼容 scoped storage。

### 3.7 国际化（F4.6 中英双语）

- **资源拆分**：`res/values/strings.xml` 为**默认（英文）**资源（app_name = "Sample Note"），`res/values-zh/strings.xml` 为中文资源（app_name = "简记"）。未覆盖语言一律回退默认英文资源（Android 资源回退链保证，无需代码处理）。
- **locale 跟随**：完全跟随系统语言（`Locale.getDefault()` 经资源系统生效），**本期不提供应用内手动切换**，不引入 AppCompatDelegate.setApplicationLocales 等切换机制。
- **Compose 字符串外置约束**：所有面向用户的字面量（菜单项、设置项、提示/错误文案、对话框按钮、contentDescription/语义描述）一律经 `stringResource()` 引用，禁止硬编码在 composable 内；TC-UI 断言文案处同步改读资源。解析层异常消息（ParseException 展示文案）也经资源映射，不按异常类型硬编码中文。
- **命名约束**：字符串键按 `screen_元素_用途` 命名（如 `reader_menu_settings`），中英同键；新增界面元素必须同时补两种语言，代码评审时检查。

2. **生效机制（`LocaleSwitcher`，core/settings）**：
   - **全 API 级**：`MainActivity.attachBaseContext` 按持久值 `createConfigurationContext` 包装 Configuration（`wrapBaseContext`；跟随系统时原样返回）。**「手动选择优先于系统语言」在此路径保证**——包装后的 Configuration 覆盖系统 locale，不依赖框架行为。
   - **API 33+**：额外调 `LocaleManager.setApplicationLocales`（`SYSTEM` → 空 `LocaleList`），由系统完成 Activity 重建，此时 `applyToFramework` 返回 `true`。
   - **API 26~32 或框架不可用（服务缺失/调用被拒）**：`applyToFramework` 返回 `false`，设置页在持久化写入完成后调 `Activity.recreate()` 使包装生效——避免「已落库但界面未变、要等下次 Activity 创建」的静默窗口；33+ 框架成功时不手动重建（不重复重建）。

### 3.8 阅读器连续滚动与 epub 原生目录（F2.16/F4.7/F4.8，M12）

**epub 目录原样呈现与锚点跳转（F2.16）**

- 目录面板数据源由「按 spine 逐章生成」改为 `Document.toc` = 文件自带目录（epub3 nav.xhtml 优先、epub2 NCX 回退，条目/标题/层级原样）；**解析层取消「第 N 章」兜底**（`EpubParser` 原 `title ?: "第 ${index+1} 章"`），`Chapter.title` 无匹配时为 null；文件无目录则 `Document.toc` 为空，顶栏目录图标隐藏（与 md 空 toc 一致），不提供任何生成式兜底。
- 解析层新增**锚点映射**：`extractWithPull2` 段级 flush 时记录最近块级祖先元素的 `id` → 产出每章 `anchors: Map<elementId, paragraphIndex>`（``<a name>` 一并视为锚点；纯图章合成空宿主段时锚点照常映射到该宿主段；**容器元素（div 等）的 id 映射到其内首个段落，容器内无段落时取最近前段落**）；`stripTagsFallback2` 降级路径无结构信息，锚点映射为空。

**跨章连续滚动（F4.7）与坐标系**

| --- | --- | --- | --- |
| `ask_ai_enabled` | Boolean | `true` | 功能总开关；关闭时既不监听剪贴板也不提供菜单发送 |
| `ask_ai_target_package` | String? | 缺失（未选择） | 目标应用包名；缺失 = 未选择（此时不提示、不发送） |
| `ask_ai_prefix` | String? | 缺失 | 提问前缀；**缺失 = 用资源默认前缀**（`settings_ask_ai_prefix_default`，zh「请解释：」/ en「Explain: 」，英文值带尾随空格故资源中加引号保留）；**显式空串 = 原文直发** |

- 新增 `Flow` + `save*` 方法（`askAiEnabled` / `askAiTargetPackage` / `askAiPrefix`），键级隔离。
- 目标应用存**包名**（非 label）：应用改名/换语言不影响，标签运行时解析。

**2. 核心逻辑（`core/askai/AskAi.kt`，纯函数 + 单一发送入口，便于单测）**

```kotlin
data class AskAiTarget(val packageName: String, val label: String)

object AskAi {
    /** 内置预设目标（D-2026-09-19-03）：即使应用未注册 ACTION_SEND 也可显式选择，发送失败由 UI 提示换一个 */
    val PRESET_TARGETS: List<AskAiTarget>  // 至少含 DeepSeek(com.deepseek.chat)；豆包(com.larus.nova)以实测包名为准

    /** 候选 = 预设中「已安装」者 ∪ 动态枚举（ACTION_SEND + text/plain 的已安装应用），按包名去重、按 label 排序、排除自身 */
    fun candidates(context: Context): List<AskAiTarget>
    /** 前缀拼接：prefix 为 null 用资源默认；空串 = 原文直发；非空 = prefix + text */
    fun composePayload(prefix: String?, defaultPrefix: String, text: String): String
    /** 是否给出提示：开启 + 已选目标 + 文本非空白 + 与上次提示的文本不同（同文重复复制不重复打扰） */
    fun shouldOffer(enabled: Boolean, targetPackage: String?, text: String?, lastOffered: String?): Boolean
    /** 提示文案里的节选（默认 20 字符，超长加省略号） */
    fun excerpt(text: String, max: Int = 20): String
    /** 构造发送 Intent：ACTION_SEND + type text/plain + setPackage(target) + EXTRA_TEXT（不弹系统分享面板） */
    fun buildSendIntent(targetPackage: String, payload: String): Intent
    /** 发送；目标缺失/无 Activity（未安装、被禁用）→ 返回 false，由 UI 提示「目标应用不可用，请在设置中重新选择」 */
    fun send(context: Context, targetPackage: String, payload: String): Boolean
}
```

- **包可见性（真机必需，2026-09-19 审查发现）**：Android 11+ 的包可见性过滤会让 `queryIntentActivities` / `getApplicationInfo` 只返回少量结果——真机实测仅看到「朗读」「蓝牙」，已安装的 DeepSeek 不在其中。故 `AndroidManifest.xml` 必须声明：
  ```xml
  <queries>
      <intent>
          <action android:name="android.intent.action.SEND" />
          <data android:mimeType="text/plain" />
      </intent>
      <!-- 预设备份：预设包名需显式声明方可查询安装状态 -->
      <package android:name="com.deepseek.chat" />
      <package android:name="com.larus.nova" />
  </queries>
  ```
  **这不是权限**：不申请任何运行时权限、不改变「不联网/不采集」红线，仅声明可见范围（`<queries>` 由系统在安装时静态处理，无用户提示）。
- **预设与枚举合并**：候选 = 预设中已安装者 ∪ 枚举结果 → 按包名去重（预设标签优先取 `loadLabel`，失败回落预设展示名）→ 按 label 排序 → 排除自身。预设存在的意义：① 补枚举缺漏（未注册 ACTION_SEND 的应用）；② 给用户稳定的可选项。发送失败（未安装/被禁用）走既有「目标应用不可用，请在设置中重新选择」提示。
- 不做 `Icon`/`ResolveInfo` 缓存（枚举仅在设置页打开对话框与发送失败回退时调用，量小）。
- 排除自身包名（本应用未注册 `ACTION_SEND`，防御性过滤）。

- `setContent` 内以 `Box` 包 `NavHost` 并挂 `SnackbarHost`（底部），供全局提示（F4.10 的「问 AI」提示与手势/剪贴板提示共用宿主）。

## 5. 关键流程

### 5.1 打开 epub 并阅读

```
用户选文件 → SAF 返回 URI → DocumentRepository 识别格式(EPUB)
→ EpubParser 解压 zip 到私有缓存(cache/epub/<hash>/，后台, 显示加载圈, 可被取消)
   → 解析 OPF/manifest/spine + 逐章 XHTML（文本块 + 图片块 + CSS 子集样式提示，F2.14/F2.15）
   → 得到 Document(多章, 含 blocks 富文本块)
→ 查 ProgressRepository 恢复上次章节/段落 → 渲染（段落 item 内联图片/样式，F2.14/F2.15）
→ 用户切 NO_WRAP → 记录当前段落索引 → 以 no-wrap 重组 → 滚动回原段落
```

### 5.2 编辑并保存 txt

```
ReaderScreen 点"编辑" → EditorScreen 载入全文文本
→ 用户修改(dirty=true, 草稿防抖写入 edit_recovery/)
→ 点保存 → 先写缓存临时文件并校验 → openOutputStream("wt") 写回
   (Provider 不支持 "wt" 时回退 "w" 重写; 仍失败提示另存, 临时文件保留)
→ 保存成功清 dirty、删草稿 → 返回阅读界面按新内容重新解析显示
```

### 5.3 打开 md 并查看目录跳转（F2.13）

```
用户打开 md → PlainTextParser 解析(后台) → Document(单章 + toc 目录锚点)
→ 顶栏「目录」图标(toc 为空时隐藏, F4.5) → 目录底部弹层(按 level 缩进, 当前标题高亮)
→ 点击目录项 → 滚到标题所在段落(源码视图直接滚 / 预览视图经 block↔段落索引映射)
→ 滚动后 firstVisibleParagraph 上报 → 进度持久化(F2.8), 重开回到该标题处
```

## 6. 非功能设计要点

- **性能**：解析全部在 IO 协程；txt 分块加载（首块 200 段，滚动到底部阈值时预取下一块，块 200 段）；渲染侧 `LazyColumn` 已按段落懒排版，故 M8b 将原"预取窗口前后各 200 段（卸载远端）"简化为**单向追加不卸载**——内存上限即全文文本（txt ≤ 15 MB 级可接受），段落索引稳定、进度恢复不漂移；长列表避免一次性排版整本书。md 目录提取为解析中的单次线性扫描（跳过代码块），无额外 IO 与内存开销。
- **稳定性**：解析失败按 `ParseException` 子类型差异化提示（格式不支持 / 缺少 OPF / 内容损坏 / 文件过大 / 权限不足），不统一报"文件损坏"；OOM 单独捕获并提示"文件过大"。
- **配置变更**：ViewModel 持有全部状态，横竖屏切换/深色模式切换不丢内容与位置；编辑器另经 `SavedStateHandle`（轻量状态）+ 草稿恢复文件覆盖进程死亡场景。
- **无障碍**：主题前景/背景对比度 ≥ 4.5:1（四套预设主题均满足）；交互控件 ≥ 48dp；按钮带 `contentDescription` 支持 TalkBack。
- **混淆/发布**：release 开启 R8；解析与编码探测仅用 JDK/Android 平台 API（`XmlPullParser`、`android.icu`），无第三方库 keep 规则负担。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 非标准 epub（缺导航文件、XHTML 不规范） | 导航按 epub3 nav.xhtml → epub2 NCX → "第 N 章" 逐级降级；**正则"剥标签"降级仅在 `XmlPullParser` 抛出 `XmlPullParserException`/`IOException` 时触发**，其余解析异常走 `ParseException.MalformedContent`；降级结果以可读为准，不追求精确还原（CDATA/注释/实体等边界不作保证） |
| 编码误判 | BOM 优先 + 严格解码级联（UTF-8 → GBK → Latin-1）；仍误判时允许用户在阅读界面手动切换编码并即时重载 |
| SAF Provider 不支持 `"wt"` 截断 | 回退 `"w"` 模式重写；仍失败提示另存 |
| SAF 写回中途失败导致原文件被截断（云存储 Provider 先清后写） | 保存先写应用缓存临时文件并校验完整性，再一次写回；写回失败时临时文件保留，提示另存，用户内容不丢 |
| 草稿文件残留占用存储 | 三重清理：保存/放弃删除、最近列表移除联动删除、启动时清理 7 天前孤儿草稿 |
| SAF 持久权限失效（文件被移动/删除） | 打开时捕获 `SecurityException`，提示并移出最近列表 |
| 云盘 Provider 进程被 OEM 杀死（S1 探针实测，ColorOS + Google Drive） | 持久授权仍在但访问抛 `FileNotFoundException: No content provider`；**不得**误判为权限失效而移出最近列表；提示"文件提供方（如云盘应用）未运行，请启动对应应用后重试"，用户启动该应用后同一 URI 无需重新授权即可访问 |
| 超大 txt（几十 MB）编辑卡顿/ANR | 编辑全量加载设上限（默认 2 MB 可编辑，超出提示只读打开；真机 5MB 全量 TextField 触发 ANR） |
